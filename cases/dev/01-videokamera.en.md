# Videokamera — a baby monitor on a home PC

## Summary

A PC in the child's room turned into a camera with two-way audio: video and microphone come from a page on
the PC, viewing and talking happen from a phone. It runs today as a Windows service with autostart, HTTPS on
port 8443, password login, a PWA icon on the phone and motion notifications. It is built on the open-source
PetCam project (ISC licence) with 18 commits of my own on top.

## Problem

At night you need not only to see the child but also to hear and answer by voice. Off-the-shelf monitors
stream video to someone else's cloud, require a subscription, delay the audio and almost never offer two-way
sound. The upstream PetCam could only stream one way: no TLS, no authentication, no autostart — an open
camera in the flat after every reboot.

## Solution

1. Two-way audio over WebRTC: the PC page sends video and sound, the phone receives the stream and can send
   its microphone back ("Listen" / "Talk" buttons).
2. HTTPS on 0.0.0.0:8443 with a self-signed certificate generated on first start; a separate tool regenerates
   it when the IP changes; a Tailscale certificate is supported as an alternative.
3. Basic Auth on pages, static files and the WebSocket signalling: login and password are compared in
   constant time, the Authorization header is parsed manually.
4. Autostart as a Windows service via NSSM: StartType = Automatic, restart 5 seconds after a crash, plus an
   alternative "run at user logon" scheduled task.
5. Motion detection: the camera page diffs frames on a Canvas and posts to /api/motion; the server publishes
   a notification with a snapshot and applies a cooldown against flooding.
6. PWA viewer: manifest, service worker (caches the shell only, never touches the API or the WebSocket), and
   192/512 icons generated by a custom PNG encoder with no external dependencies.
7. Mobile UX: fullscreen viewing, a settings panel, an honest "No sound" state instead of a stuck button, and
   a fresh WebRTC offer when a viewer joins after the camera.
8. Log rotation at 1 MB plus a daily log cleanup task in Windows Task Scheduler.
9. 18 tools in tools/: certificate, ntfy, syntax and firewall checks, port status, and a UAC-elevation
   wrapper so an AI agent working without admin rights can still run privileged scripts.
10. A 307-line README: quick start, autostart, outside access, diagnostics, common problems.

## Skills demonstrated

- WebRTC: peer connection, re-ordering offer/answer when a viewer joins late.
- Signalling over WebSocket (ws) on a self-hosted server.
- HTTPS with a self-signed certificate: generation, validation, regeneration, choosing between two certificates.
- Basic Auth: manual header parsing, constant-time comparison, a whitelist of public PWA files.
- Windows services through NSSM: install, autostart, restart, status diagnostics.
- PWA and service worker: manifest, icons, caching strategy, installation to the home screen.
- Motion detection: client-side Canvas diff, server API, anti-flood cooldown, push notifications.
- Windows automation: PowerShell scripts, Task Scheduler, log rotation and cleanup.
- Privilege-escalation wrappers: a one-off UAC task for an agent without admin rights.
- Working with forks and upstream: keeping compatibility while rebranding the product.

## Stack

Node.js + Express 4, ws 8, axios, selfsigned, ip; vanilla JavaScript + Canvas + WebRTC on the client;
NSSM 2.24, PowerShell 5.1, Windows Task Scheduler; TLS: self-signed or a Tailscale certificate; remote access
over a private VPN network (Tailscale).

## Limitations

- A PWA on Android refuses to install when the manifest, service worker and icons sit behind Basic Auth, so
  those four files had to be made public (they contain no secrets).
- Fullscreen and Wake Lock on iOS only work on a user gesture, and partially.
- The Tailscale certificate is valid for a single hostname only; opening the site by IP still triggers a
  browser warning about the name mismatch.
- Certificate renewal is not automated — it has to be refreshed manually or by a scheduled task.
- The ESP32-S3 firmware from upstream is unused; the motor-control block in the viewer remains optional and
  has not been tested.
