# Echelon Beyond — мир, руководства и ассеты игры

## Коротко

Тактический roguelite о плавании по астральному океану: собственный мир, 18 томов
руководства (от истории мира до сценария и MVP), стилевые ассеты и инструментарий
производства. Сделано автором как личный игровой проект; сейчас это проработанная
документация и производственный конвейер, код игры на Godot ещё не начат.

## Проблема

Игровая идея такого масштаба живёт в голове ровно до первого черновика: мир, народы, боевая
система, музыка, визуальный стиль и сценарий не сходятся между собой, а визуал из генеративных
моделей получается «разношёрстным» и не узнаваемым. Нужен был способ удержать целостность
вымышленного мира и производственный процесс, который не разваливается на 10-й итерации.

## Решение

1. Руководство мира из 18 томов (том 0 и тома I–XVIII) в docs/GUIDE: введение, история мира,
   народы, бои и враги, техномагия, музыка, визуал, персонажи, сценарий, квесты, MVP.
2. Репозиторий как производственная система: AGENTS.md описывает контракт результата
   (каждая задача оставляет папку в deliveries/ с SUMMARY.md и файлами), правила git и запреты.
3. Структура проекта зафиксирована в docs/STRUCTURE.md: src/ (Godot), assets/ (art, audio,
   animation, references, lora-датасеты), docs/ (GUIDE, ART, TECH), tools/, deliveries/, _archive/.
4. Kanban-доска на базе Cline: карточки задач, колонки «Очередь / В работе / Готово», запуск
   из start-kanban.cmd, доступ к доске с телефона и ноутбука, отдельная легенда доски в docs/TECH.
5. Разделение труда автор ↔ ИИ-агенты: 37 собственных коммитов, а поверх — 51 агентский
   (канбан-чекпоинты и агенты, работающие по контракту из AGENTS.md).
6. Стиль игры зафиксирован через LoRA «Фрески Мереи» (см. кейс 05), промты и негативы хранятся
   в репозитории как версионируемые файлы.
7. Арт-пайплайн: 141 кандидат главного меню (203 МБ) в assets/art/ui/menu, отбор через контактные
   листы, метаданные PNG, палитровые метрики и правила приёмки.
8. Датасет для обучения: 50 кадров + 50 капшенов в assets/lora/{train,captions}, отбраковка с
   объяснением причин (assets/lora/rejected), отдельные прогоны-калибровки.
9. Доставка результатов: deliveries/ + локальная страница результатов и рассылка файлов на
   устройства (см. кейс 07).
10. Документация производства в docs/ART (MENU-ART 786 строк, LORA-DATASET 269, LORA-INSTALL 219,
    ZYBB1-BACKGROUND 185, REFS-NOTES 50) и docs/TECH (доступ, стриминг, передача на ПК, Wake-on-LAN).

## Демонстрируемые навыки

- Проектирование вымышленного мира: 18 томов документации, согласованных между собой.
- Производственная дисциплина: контракт результата, SUMMARY.md к каждой задаче, архив вместо удаления.
- Организация большого репозитория: строгие правила размещения файлов и запрет мусора в git.
- Управление работой ИИ-агентов: правила в AGENTS.md, доска задач, отдельные авторы коммитов.
- Версионирование творческого процесса: промты, рецепты и отчёты QC лежат в git рядом с ассетами.
- Python + PowerShell инструментарий (232 файла) под конкретные производственные операции.
- Работа с ассетами: 141 вариант меню, датасет LoRA, референсные подборки, контактные листы.
- Документирование инфраструктуры: доступ, стриминг, передача на ПК, пробуждение по сети.

## Стек

Godot 4.6.3 (движок выбран и установлен; src/ пока пуст), Markdown-документация, Python 3.10/3.11
и PowerShell 5.1 для инструментов, Fooocus + API для генерации, kohya_ss для обучения LoRA,
Cline Kanban для задач, приватная VPN-сеть и Taildrop для доставки на устройства.

## Что не получилось / ограничения

- Код игры не начат: src/ содержит только заглушки, играбельного прототипа нет.
- 18 томов руководств существуют в форматах .docx/.txt — единая сборка (один PDF/сайт) пока не собрана.
- Тяжёлые залежи ассетов (141 кадр меню, датасет) сознательно не коммитятся в git и живут отдельно.
- Автоматические тесты как таковые не заведены — контроль качества держится на скриптах QC и глазах автора.
- Главное меню так и не выбрано окончательно: 18 итераций промта дали кандидатов, но финального
  кадра в отчётах нет.
- Часть документации описывает конкретное окружение автора (устройства, сеть) — для публикации
  потребуется обезличивание.
