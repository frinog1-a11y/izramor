# Echelon Beyond: рабочий пайплайн «телефон → ноутбук → домашний ПК»

## Коротко

Инфраструктура вокруг игрового проекта: домашний ПК как источник истины и «фабрика» (репозиторий,
ИИ-агент, генерация, обучение), ноутбук как рабочее место, телефон как пульт. Результаты задач
автоматически попадают на страницу выдачи и рассылаются на устройства, задачи ставятся на доску
через Kanban, ПК можно разбудить по сети и к нему подключиться стримингом.

## Проблема

Проект делается между двумя компьютерами и телефоном: на ноутбуке удобно писать и смотреть,
но он часто выключен; на домашнем ПК стоит видеокарта, репозиторий и ИИ-агент. Файлы терялись
между машинами, доступ к доске задач был только с одного места, а «результат готов» означало
«надо не забыть скопировать».

## Решение

1. Правило «источник истины — домашний ПК»: всё, что должно пережить выключение ноутбука,
   выполняется дома; ноутбук — рабочая копия и место просмотра.
2. Контракт доставки: каждая задача обязана оставить папку deliveries/<задача>/ с SUMMARY.md
   (что сделано, чем, вердикт числами, что осталось).
3. Локальный сервер выдачи результатов: папка deliveries автоматически видна на странице,
   открывающейся с телефона и ноутбука по приватной сети.
4. Рассылка файлов на устройства через Taildrop (без прав администратора на приёмнике);
   офлайн-устройство даёт TIMEOUT, и это не считается провалом задачи.
5. Обратное направление: задача на ноутбуке периодически сама забирает результаты с домашнего ПК.
6. Kanban-доска задач, запускаемая одной командой: колонки «Очередь / В работе / Готово»,
   доступ к доске с телефона и ноутбука, вход только через приватную сеть.
7. Документированный доступ: руководства по подключению, стримингу рабочего стола,
   передаче файлов и пробуждению ПК по сети (Wake-on-LAN).
8. Локальные LLM как альтернатива облаку: свои провайдеры моделей, локальный сервер моделей,
   скрипты автозапуска, проверки и снятия статуса, отдельный скрипт для сетевого доступа к нему.
   Управление этим хозяйством поручено агенту — Cline по скриптам поднимает сервер модели,
   проверяет его доступность, отправляет тестовый запрос и снимает статус, чтобы человеку
   не держать в голове команды трёх разных инструментов (Ollama, LM Studio, сетевой доступ).
9. Диагностический арсенал (32 скрипта): проверка окружения, портов, процессов, окон, IP,
   кодировок и концов строк, поиск по дереву проекта, просмотр логов.
10. Управление и настройка ПК: SSH, Wake-on-LAN, автологин, стриминг — 11 скриптов в tools/setup.

## Демонстрируемые навыки

- Проектирование распределённого рабочего процесса между несколькими устройствами.
- Автоматизация доставки артефактов: сервер выдачи, рассылка на устройства, обратная синхронизация.
- Работа с приватной VPN-сетью как единственным каналом доступа (доска без пароля, но вне интернета).
- Пробуждение и включение ПК: Wake-on-LAN, автологин, SSH, удалённый стриминг.
- Локальные LLM: разворачивание, автозапуск, проверки доступности, сетевой доступ.
- Дисциплина контракта результата: у каждой задачи свой отчёт с числами и остатком работ.
- Диагностика на Windows: скрипты по портам, процессам, окнам, переменным окружения.
- Документирование инфраструктуры так, чтобы её мог повторить другой человек или агент.

## Стек

Windows 10, PowerShell 5.1, Python 3.10, приватная VPN-сеть (Tailscale) и Taildrop,
локальный HTTP-сервер для выдачи результатов, Cline Kanban, Ollama и LM Studio (локальные модели),
Wake-on-LAN, SSH, стриминг рабочего стола, Godot MCP для управления движком.

## Что не получилось / ограничения

- SMB-шара с домашнего ПК недоступна (ограничение учётной записи) — файлопомощь пришлось строить
  на Taildrop и HTTP-странице.
- OneDrive как канал передачи не подошёл: процесс на домашнем ПК не запущен.
- Если устройство офлайн, доставка не проходит; повторная отправка — вручную, когда устройство вернётся.
- Доска задач доступна только через приватную сеть, вход по коду отключён сознательно.
- Часть документации содержит конкретные адреса и имена устройств автора — для публикации нужно обезличивание.
