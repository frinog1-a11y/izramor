# «Между строк чертежа» — база знаний нормоконтролёра

## Коротко

Публичная база знаний по ЕСКД: карточки типовых ошибок чертежей, конспекты ГОСТов, чек-листы
по типам документов — связанные двусторонними ссылками и опубликованные статическим сайтом
с поиском и графом связей. Сделана под ежедневную работу нормоконтролёра (супруга автора).
Сейчас в базе 24 карточки ошибок в 7 категориях, 46 конспектов ГОСТов и 29 типов документов;
сайт живой, обновляется обычным пушем.

## Проблема

Нормоконтролёр ежедневно проверяет десятки чертежей и документов: каждая ошибка требует поиска
ГОСТа, проверки смежных ошибок и сверки с примерами. Без единой базы это часы работы, а одни и
те же замечания повторяются из документа в документ. Дополнительное условие: правки нужно
делать прямо с рабочего ПК, где нет ни Git, ни возможности что-то установить.

## Решение

1. Единая база в Markdown (хранилище Obsidian): папки по разделам, у каждой папки свой индекс.
2. Публикация статического сайта: Quartz 4 + GitHub Pages, сборка и деплой из GitHub Actions.
3. Двусторонние ссылки «ошибка ↔ ГОСТ ↔ документ» + автоматический аудит связей: 29 из 29
   документов ссылаются на ошибки, 46 из 46 ГОСТов — на ошибки по ним.
4. Карточка ошибки по единой схеме: категория, ГОСТ, документ, «как выглядит / как правильно»,
   примеры, пункт ГОСТа, смежные ошибки.
5. Граф связей (D3 + Pixi): узлы окрашены по категориям, размер зависит от числа связей,
   у крупных узлов есть подписи, есть мягкая кластеризация по разделам.
6. ИИ-конвейер пополнения базы: на сайте заполняется одно поле → создаётся issue по шаблону →
   workflow (только для владельца репозитория) отправляет текст в DeepSeek → генерируется заметка →
   сборка → публикация. Ключ живёт только в секретах Actions, логи проходят через scrub(),
   ответ модели ограничен max_tokens.
7. Веб-редактор базы (Sveltia CMS) и кнопки «Править на GitHub» — чтобы править заметки в браузере
   с рабочего ПК без Git.
8. Тема «Инженерный дневник»: собственная палитра и SCSS, светлая и тёмная темы, кнопка «наверх»,
   адаптивная вёрстка, кастомный астральный фон с частицами.
9. Пасхалка: скрытая страница с мини-игрой (см. кейс 03), исключённая из поиска, графа, sitemap,
   RSS и снабжённая noindex.
10. Проверки до публикации: tsc --noEmit, prettier --check, скриптовый аудит связей и метаданных,
    юнит-тест поиска, функциональные тесты на заглушках (когда в системе вообще нет браузера).

## Демонстрируемые навыки

- Построение базы знаний: схема заметок, шаблоны, метаданные, двусторонние связи.
- Генератор статических сайтов Quartz 4: кастом темы, раскладки, компонентов, стилей.
- Точечное вмешательство в чужое ядро: все правки помечены патчами, чтобы обновления не ломали проект.
- CI/CD на GitHub Actions: сборка, деплой на Pages, отдельная задача «из issue в заметку».
- ИИ-конвейер: интеграция LLM в CI, поддержка нескольких провайдеров по префиксу ключа,
  санитизация логов, ограничение объёма и стоимости ответа.
- TypeScript и визуализация данных (D3, Pixi) с настройкой конфигураций графа.
- Проверяемость: автоматический аудит ссылок и связей вместо ручной вычитки.
- Работа без графической среды: тесты на заглушках document/canvas/AudioContext.
- Документация для передачи контекста: HANDOFF.md с состоянием, грабли, открытые вопросы.

## Стек

Quartz 4.5.2 (TypeScript, SCSS), Node.js 22+, D3 + Pixi, Obsidian/Markdown, GitHub Actions
+ GitHub Pages, Sveltia CMS, DeepSeek API (опционально OpenRouter/Groq/Ollama), Prettier.
Ядро Quartz почти не правилось — изменения оформлены помеченными патчами.

## Что не получилось / ограничения

- Конвейер «issue → заметка» намеренно ограничен: срабатывает только для задач от владельца репозитория.
- В системе нет браузера, поэтому визуальная проверка заменена сборкой и скриптовыми тестами —
  живой вид страниц автор проверяет вручную с телефона/рабочего ПК.
- Инлайн-скрипты внутри markdown запрещены сборщиком, поэтому логика игры живёт в статическом JS.
- 27 документов пока без обратной ссылки от карточек ошибок.
- Раздел примеров (сканы «плохо/хорошо») пуст.
- Доска задач (GitHub Projects v2) настраивается только руками: нет gh CLI и нужного скоупа токена.
- Деплой не мгновенный: 2–8 минут; браузер кеширует индекс поиска, нужен жёсткий refresh.
- Личное имя автора в проекте не раскрывается — в README стоит заглушка.
