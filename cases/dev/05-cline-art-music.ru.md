# Оркестрация Cline для арта и музыки

## Коротко

Производство визуала и звука для игрового проекта через локальные генеративные модели под
управлением ИИ-агента: обученная с нуля стилевая LoRA, 18 итераций промта для главного меню,
инструменты контроля качества по числам (палитра, метаданные, контактные листы) и заготовки
музыки под локальный музыкальный генератор. Всё на одной домашней видеокарте на 8 ГБ.

## Проблема

Генеративный визуал легко получить, но трудно сделать узнаваемым: кадры разъезжаются по стилю,
один и тот же промт даёт то фотореализм, то мультик, а «на глаз» невозможно понять, почему
итерация стала хуже. Плюс железное ограничение: 8 ГБ видеопамяти — одновременно обучение
модели и генерация не помещаются. Нужен был процесс, где решение принимается по метрикам,
а не по вкусу, и где инструменты воспроизводимы.

## Решение

1. Собран датасет стиля: 50 кадров с капшенами, отбраковка слабых кадров в отдельную папку
   с объяснением причин и повторная генерация проблемных с явным субъектом в промте.
2. Обучена стилевая LoRA «Фрески Мереи» на портативном kohya_ss: rank 32 / alpha 16, только
   U-Net, 1500 шагов, AdamW8bit, fp16, база — SDXL-чекпоинт 6,94 ГБ.
3. Скорость обучения выведена из тупика по диагностике: четыре прогона вместо одного —
   от 88–119 с/шаг до 5,9–6,5 с/шаг (2,4 ч вместо 36–50 ч), потому что мешала не ошибка,
   а занятая генератором видеопамять.
4. Включён TF32 без флага в сборке kohya — через собственный шим sitecustomize.py в PYTHONPATH
   (замер матмула: 36,78 мс → 20,10 мс, ускорение 1,8x).
5. LoRA установлена в Fooocus и подключена к генерации (слоты 1–5), A/B-тест «с LoRA против
   без LoRA» с одним сидом: вердикт по sha1 и по метрикам палитры, а не «на глаз».
6. Свой стилевой пресет Fooocus («Echelon Fresco») с идемпотентной установкой скриптом.
7. Промты и негативы версионируются как файлы в git: 18 итераций (v4…v18), свипы по 20 кадров,
   отдельные промты для элементов сцены (корабль, кракен, солнце).
8. Диагноз «промт не влезает в CLIP»: 2 618 символов промта не помещались в 77 токенов, сюжет
   уезжал в хвост, плюс молча работал не тот чекпоинт — лечение: короткий промт, CFG 6.5,
   качественный режим, запрет лишних объектов в негативе.
9. Контроль качества по числам: палитровое сравнение кадров, проверка метаданных PNG,
   автоматические контактные листы для отбора глазами, скрипт отбраковки.
10. Музыкальное направление: локальный генератор ACE-Step 1.5 и три волны пакетной генерации —
    7, 86 и 129 треков (FLAC), экспорт в mp3 (84 и 126 файлов), отдельная музыкальная LoRA,
    а также библиотека проекта с 11 категориями (ambient, слои, боссы, финалы, шанти, гимн),
    39 текстовыми брифами и 4 отобранными mp3.

## Роль Cline в пайплайне

Пайплайн собран так, что рутинные операции выполняет агент, а решения остаются за человеком.
Конкретные задачи, которые делал Cline:

1. Запуск батчей генерации в Fooocus: подготовка кадров по списку промтов, ожидание очереди,
   сбор результатов в нужную папку и отчёт о том, что получилось.
2. Сбор метрик контроля качества: палитровое сравнение кадров, чтение метаданных PNG, сверка
   версий по хешам файлов — то есть подготовка чисел, по которым потом принимается решение.
3. Версионирование промтов и негативов: сохранение рецептов как файлов в git, чтобы каждая
   итерация стиля оставалась воспроизводимой.
4. Отбраковка слабых кадров: перенос неудачных прогонов в отдельную папку с причинами
   и повторная генерация с изменённым промтом.
5. Обучение LoRA: стейджинг датасета, запуск тренера kohya_ss, ведение лога обучения
   и диагностика по счётчикам GPU (поиск узкого места по памяти и мощности).
6. Подключение результатов к генератору: идемпотентная установка собственного пресета стиля
   и патч драйвера, чтобы LoRA попадала в слоты генерации.
7. Музыкальная ветка: запуск пакетной генерации ACE-Step по волнам, экспорт в mp3,
   учёт треков по категориям библиотеки.

Что оставалось за человеком: решения по стилю, пороги отбора по метрикам, финальный выбор
кадра главного меню и вкусовая проверка — метрики отсекают явный брак, но не заменяют слух и глаз.

Чего агент не мог делать сам: смотреть кадры и слушать музыку — у него нет ни браузера,
ни звука, ни зрения. Обход: агент готовил числа и контактные листы, а выбор делал человек
по этим материалам.

## Демонстрируемые навыки

- Обучение SDXL-LoRA с нуля: датасет, капшены, гиперпараметры, отбраковка, переобучение по фактам.
- Оптимизация под 8 ГБ VRAM: измерение по счётчикам GPU, поиск узкого места, обоснованные решения.
- Обход ограничений инструмента: включение TF32 шимом через PYTHONPATH.
- Версионирование промтов и рецептов как инженерных артефактов (18 итераций с историей).
- Автоматическая оценка генеративного контента: палитровые метрики, sha1, контактные листы.
- Работа с API генератора изображений (Fooocus) и идемпотентный патч его драйвера.
- Построение датасетов референсов: подборки по стилям, скрипт загрузки, документирование.
- Подготовка музыкального продакшена: категоризация, брифы, локальный генератор музыки.

## Стек

Fooocus (SDXL) + его API и свой стилевой пресет, kohya_ss-portable для обучения LoRA,
ComfyUI и Wan 2.2 для видео-направления, ACE-Step 1.5 для музыки, Python 3.11 и скрипты
контроля качества, PowerShell, RTX 3060 Ti 8 ГБ, LM Studio для локальных LLM.

## Что не получилось / ограничения

- 8 ГБ VRAM: обучение и генерация не уживаются, их пришлось полностью развести по времени.
- Кадр главного меню окончательно не выбран — 18 итераций дали кандидатов, финального решения нет.
- Музыка: из ~10 категорий в библиотеку проекта отобрано 4 mp3, хотя сгенерировано ~300 треков —
  слушательский отбор и сведение ещё предстоят.
- Пакетная выгрузка идёт в FLAC/MP3 десятками файлов (десятки гигабайт на диске) — библиотека
  требует чистки и каталогизации.
- Подборки референсов заполнены частично: две группы скачаны, четыре остались пустыми.
- Видео-направление (ComfyUI + Wan 2.2) развёрнуто, но результат в отчётах не зафиксирован.
- Проверка «глазами» обязательна: палитровые метрики отсекают явный брак, но не вкус.
